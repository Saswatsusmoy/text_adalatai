Assignment pillar 1: measure and reduce Indic token inefficiency. Approach: (1) cross-family survey to identify the failure mode of Devanagari-blind tokenizers, then (2) a full 35-config matrix on the domain corpus to freeze the best SentencePiece configuration for legal EN-HI.

1. Cross-family survey (motivation)

What was measured on the raw assignment bitext (1,458 EN-HI pairs before the Hindi line-join step; the join then produced 1,422 longer, complete units -- see Pipeline):

  • Hindi chars per token (higher = denser packing)
  • HI / EN token ratio (closer to 1 = less Indic overhead)
  • Total tokens on the corpus (proxy for context length + cost)
  • Whether Devanagari exists as first-class pieces or falls back to UTF-8 bytes
FamilyExamplesHindi on legal text
Char-aware SentencePiece Unigram domain SPM, Gemma-class SP Strong -- Devanagari first-class
Multilingual BPE with Dev pieces NLLB, OpenAI o200k Good packing
Byte-level BPE many Llama-line models Weak -- often 0 Dev vocab entries; UTF-8 byte split; ~1.1-2.7x HI cost
Important distinction

The failure mode is byte-level / Devanagari-blind BPE, not "all BPE". SentencePiece model_type=bpe is Unicode-aware and is a different animal -- see matrix results below.

A 41k domain SPM on ~14M chars of legal Hindi beats Gemma-262k and GPT-4o-200k on packing for this bench. Legal terms often encode as single pieces: न्यायालय, अपीलार्थी, अनुच्छेद, अधिकारिता. This established the direction: build a proper domain SPM on the full Stage A + assignment train corpus and sweep the design space.

2. Full 35-config tokenizer matrix

SentencePiece has ~10 knobs that meaningfully affect legal-domain packing. Rather than hand-picking a single freeze, we ran the full Cartesian for the primary axes plus a one-at-a-time ablation for secondary axes. 35 tokenizers trained on H200 (48 cores, parallel-6, ~30 min total wall clock).

Corpus + Firewall

All matrix models train on the v2 legal corpus: Stage A (MILPaC + Anuvaad, ~993k pairs) + assignment train only. Dev/test docs are hard-excluded in src/tokenizer/prepare_spm_corpus.py. So all held-out numbers below use SPMs the target text was never in.

  • v2_joint corpus: 291M chars, 1.99M lines (EN + HI); deduped to 480MB / 1.95M lines with max_sentence_length=4096
  • v2_hi corpus: 139M chars, 994k lines (HI only)

Method

Phase 1 -- main matrix (20 configs, all defaults): {unigram, bpe} × {16k, 32k, 41k, 48k, 64k} × {v2_joint, v2_hi}.

Phase 2 -- secondary-axis ablation (15 configs; 5 single-axis toggles on top-3 Phase-1 joint bases -- bpe_64k, unigram_64k, bpe_48k): byte_fallback, character_coverage=0.9995, split_digits, split_by_unicode_script, user_defined_symbols=22 legal EN+HI protected terms.

Code: src/tokenizer/matrix_configs.py (TokenizerConfig dataclass, 14 fields, presets), train_matrix.py (ProcessPoolExecutor, subprocess-per-config, resumable manifest), bench_matrix.py (auto-discovery + legal-term probe + UNK rate). Make: tokenizer-matrix-phase1 / -phase2 / -bench.

Reads:

  • Packing scales with vocab up through 64k (4.30 → 4.70). Diminishing returns above 41k (~1.4% packing gain each doubling).
  • BPE vs Unigram is a wash. Unigram wins 32k, BPE wins 48k, tied at 64k. Effectively equivalent on this corpus + vocab budget -- so choice of model_type is not a lever here.
  • Legal-HI single-piece probe rate is 100% for all 10 joint models (न्यायालय, अनुच्छेद, अपीलकर्ता, ... always one token).
  • Legal-EN single-piece probe rate is 100% on joint (Section, Writ, Petition, Appellant, ... always one token). 0-50% on v2_hi -- HI-only fragments English, unusable for MT.
  • UNK rate = 0.00% everywhere because character_coverage=1.0.

Ranking

  1. bpe_64k_bf / unigram_64k_bf -- HI c/t 4.695, total 10,027-10,040, byte_fallback for robustness. Tied best.
  2. bpe_64k / unigram_64k baseline -- same packing, no byte-fallback.
  3. bpe_48k -- HI c/t 4.638, 10,166 total; 16k fewer vocab rows than 64k.
Freeze decision

SPM_V2_PRIMARY stays sentencepiece_legal_v2_joint_full_41000.model (Unigram 41k).

  • Track D shipped uses NLLB native tokens, so changing v2 SPM affects no shipped output.
  • Existing Track C artifacts and configs reference the 41k freeze.
  • +7% packing gain (4.37 → 4.695) doesn't justify churn for a track that lost dual-policy in §26.

Recommendation for any future Track C rebuild (C1a from-scratch or fresh C1c-style extend): bpe_64k_bf or unigram_64k_bf.

3. Integration strategy (two tracks)

TrackIdeaOutcome
D production Keep NLLB native tokenizer; adapt model with LoRA Shipped (A2)
C science Domain SPM + model adapt / vocab-extend C0 freeze done; C1c quality fail on dual policy

Why production keeps NLLB tokens: packing wins from domain SPM do not automatically become quality wins after short LoRA. Vocab surgery without long embedding warm-up lost dual-policy quality (Track C pages). For legal fidelity, LoRA on stock NLLB won.

4. Followups not run

  • MT-quality run (C1c-style vocab extend) with the matrix winner -- packing is not translation quality.
  • Rank sensitivity of LoRA on the extended-vocab NLLB.
  • Subword regularization during MT training (Unigram sampling alpha, BPE-dropout).
  • Corpus expansion: repeat matrix with WikiMatrix + FLORES lines mixed into v2_joint.
