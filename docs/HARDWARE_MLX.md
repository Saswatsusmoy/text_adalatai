## Two backends (both local)

| Backend | Use for | Strength |
|---------|---------|----------|
| **MLX / mlx-lm** | Decoder-only LLM LoRA (1B-3B, prefer **4-bit**), generation | Native Apple Silicon, unified memory aware |
| **PyTorch MPS** | HF **seq2seq** MT: NLLB, InLegalTrans, IndicTrans2-class | Existing HF enc-dec stack; no full mlx-lm parity for NLLB |

**Important:** `mlx-lm` is **not** a drop-in for NLLB/InLegalTrans (encoder-decoder).  
Track D classic legal MT stays on **PyTorch MPS** (or CPU fallback).  
LLM-as-translator + LoRA path stays on **MLX**.

## Model sizing on 16GB M4

| Workload | Recommendation |
|----------|----------------|
| Zero-shot NLLB-600M | OK on MPS |
| Zero-shot InLegalTrans ~1B | OK on MPS if careful; close other apps |
| LoRA 1B-3B 4-bit (mlx-lm) | **Primary MLX train path** |
| LoRA 7B 4-bit | Possible batch=1, short seq only; risk OOM |
| Full FT 1B+ | Avoid on 16GB |
| Stage A full 992k pairs | Prefer **subsample** first (MILPaC + HC + 50k-100k judiciary) |

Hints from profiler:

- `max_batch_hint`: **1**
- `sequence_length_hint`: **256** (try 512 only if memory allows)
- `quantization`: **4-bit preferred** for LLM path

## Map to dual tracks

### Track D (defaults) -- local

1. **Zero-shot** with PyTorch MPS:
   - `facebook/nllb-200-distilled-600M`
   - `law-ai/InLegalTrans-En2Indic-1B` (if loads in memory)
2. **Stage A/B LoRA** on seq2seq via PEFT + MPS if it fits; else freeze most layers / smaller NLLB only.
3. Optional parallel story: small **MLX** instruct model LoRA as "LLM translator" baseline (uses **model tokenizer**, not our SPM).

### Track C (custom SPM `joint_full_41000`) -- local

| Approach | 16GB + MLX fit |
|----------|----------------|
| C1a small enc-dec trained with our SPM | Feasible if model is small; custom training loop (not stock mlx-lm) |
| C1b emb resize + LoRA on small model | Needs framework that allows vocab change |
| C1c vocab-extend NLLB/IT2 | MPS/PEFT; memory tight |
| mlx-lm LoRA without vocab change | Easy on MLX but **does not use** `SPM_V2_PRIMARY` |

Honest split: **MLX for LLM LoRA demos**; **custom SPM story needs a training path that loads `SPM_V2_PRIMARY`**. That may be a small HF model on MPS or a custom MLX model -- not "mlx_lm.lora on Mistral" alone.

## Operational rules (local)

1. Close browsers / other heavy apps before train.
2. Batch size 1; grad accum for effective batch.
3. Max length 256 to start.
4. Checkpoint often; watch Activity Monitor memory.
5. Do not assume CUDA bitsandbytes; use MLX quant or HF MPS-friendly PEFT.
6. Re-run `profile_hardware.py` after OS upgrades or RAM changes.
